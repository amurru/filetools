A collection of file management and analysis tools, built with Go. Every tool
is available both as a command and through a graphical interface.

## Features

### Current Tools

- **dupfind**: Find duplicate files in a directory tree by comparing file hashes. Efficiently identifies identical files regardless of filename or location.
- **dirstat**: Analyze directory and subdirectories for comprehensive file statistics including sizes, types, and utilization percentages.
- **rename**: Rename files in a directory using pattern matching and sed-like replacements.
- **organize**: Sort files into per-category subdirectories by type, extension, modification date or size.
- **size**: Analyze how much space the files of a directory tree take up and report the largest ones.

### Key Features

- **Multiple Output Formats**: Support for text, JSON, XML, and HTML output formats
- **File Output**: Redirect output to files instead of stdout
- **Flexible Hashing**: Choose from MD5, SHA1, or SHA256 hash algorithms
- **File/Directory Exclusions**: Exclude files and directories from processing with pattern matching and file type filtering
- **Structured Data**: JSON/XML output provides machine-readable duplicate file information with metadata
- **Rich HTML Reports**: Generate professional HTML reports with styling, statistics, and interactive features
- **Comprehensive Metadata**: All structured outputs include execution context and branding information
- **Graphical Interface**: The same tools in a desktop window, with previews before anything is moved or renamed

### Planned Tools

- File content search
- Disk usage by owner

## Usage

### dupfind

Find duplicate files in a directory tree with flexible output options.

#### Basic Usage

Find duplicate files in a directory:

```bash
filetools dupfind /path/to/directory
```

If no directory is specified, it uses the current directory:

```bash
filetools dupfind
```

#### Output Formats

Choose from multiple output formats:

```bash
# Text output (default)
filetools dupfind /path/to/directory

# JSON output
filetools dupfind -o json /path/to/directory
filetools dupfind -j /path/to/directory

# XML output
filetools dupfind -o xml /path/to/directory
filetools dupfind -x /path/to/directory

# HTML output (generates a styled web page)
filetools dupfind -o html /path/to/directory
filetools dupfind -w /path/to/directory
```

#### File Output

Redirect output to a file instead of stdout:

```bash
# Save results to a file
filetools dupfind -f results.txt /path/to/directory
filetools dupfind -o json -f duplicates.json /path/to/directory
filetools dupfind -w -f report.html /path/to/directory
```

#### Hash Algorithms

Choose the hash algorithm for file comparison:

```bash
# Use different hash algorithms (default: md5)
filetools dupfind -H sha256 /path/to/directory
filetools dupfind -H sha1 /path/to/directory
filetools dupfind -H md5 /path/to/directory
```

#### Size Range

Only consider files within a size range:

```bash
# Ignore files smaller than 1MB
filetools dupfind --min-size 1MB /path/to/directory

# Ignore files larger than 100MB
filetools dupfind --max-size 100MB /path/to/directory

# Combine both
filetools dupfind --min-size 1M --max-size 500M /path/to/directory
```

Sizes accept plain byte counts or a unit suffix: `K`, `M`, `G`, `T` and their
`KB`, `MB`, `GB`, `TB` variants.

#### Performance

Large files are fingerprinted on their first 64KB before they are read in
full. Only files that share both a size and a fingerprint are hashed
completely, which avoids reading large files that cannot be duplicates.

#### Combined Usage

Combine multiple options:

```bash
# Generate JSON report with SHA256 hashes, save to file
filetools dupfind -H sha256 -o json -f report.json /path/to/directory

# Create HTML report with MD5 hashes
filetools dupfind -H md5 -w -f analysis.html /path/to/directory
```

### Exclusion Flags

Exclude files and directories from processing while still reporting them in the output.

#### File Exclusions

Exclude files matching patterns or file types:

```bash
# Exclude specific file patterns (globs)
filetools dupfind --exclude-file "*.log,*.tmp,cache/*" /path/to/directory

# Exclude by file type (matches extensions)
filetools dupfind --exclude-file "*.jpg,*.png,*.gif" /path/to/directory

# Combine with other options
filetools dirstat --exclude-file "*.log,*.tmp" -o json /path/to/directory
```

#### Directory Exclusions

Exclude entire directories matching patterns:

```bash
# Exclude common directories
filetools dupfind --exclude-dir "node_modules,.git,build" /path/to/directory

# Exclude by pattern
filetools dirstat --exclude-dir "temp*,cache*" /path/to/directory
```

#### Combined Exclusions

Use both file and directory exclusions together:

```bash
filetools dupfind --exclude-file "*.log,*.tmp" --exclude-dir "node_modules,.git" /path/to/directory
```

#### Exclusion Output

Excluded items are listed in the "Exclusions" section of all output formats:

**Text Output:**

```
Excluded files and directories:
- node_modules (dir_pattern)
- cache/file.log (file_pattern)
- temp/image.jpg (file_type)
```

**JSON/XML Output:**
Excluded items are included in the `exclusions` array with `path` and `reason` fields.

**HTML Output:**
Exclusions are displayed in a sortable table with professional styling.

### organize

Sort files into per-category subdirectories.

#### Basic Usage

Preview how the files of a directory would be organized:

```bash
filetools organize /path/to/directory
```

Group the files by a different criteria:

```bash
# One directory per file extension
filetools organize --by extension /path/to/directory

# One directory per month of the modification date
filetools organize --by date /path/to/directory

# One directory per size range
filetools organize --by size /path/to/directory
```

Move the files into a separate destination directory:

```bash
filetools organize --dest /path/to/sorted --force /path/to/directory
```

#### Categories

| `--by` | Example directory | Description |
| --- | --- | --- |
| `type` | `images/` | Broad categories: images, video, audio, documents, archives, code, data, other |
| `extension` | `png/` | One directory per file extension |
| `date` | `2024-03/` | One directory per month of the modification date |
| `size` | `1 MB - 10 MB/` | One directory per size range |

#### Dry Run (Default)

By default the command only reports what it would do:

```bash
filetools organize /path/to/directory
```

To actually move the files:

```bash
filetools organize --force /path/to/directory
```

Existing files at the target are never replaced unless `--overwrite` is given.

#### organize Flags

- `--by string`: Group files by type, extension, date or size (default "type")
- `--dest string`: Destination directory (default: the scanned directory)
- `--force`: Move the files (disables dry-run)
- `--overwrite`: Replace files that already exist at the target
- `--include-hidden`: Also organize hidden files
- `--category string`: Only organize files belonging to this category

### size

Analyze how much space the files of a directory tree take up.

#### Basic Usage

```bash
filetools size /path/to/directory
```

Report more of the largest files:

```bash
filetools size --top 25 /path/to/directory
```

The report contains the total file count, total size, directory count, the
distribution of the files over size ranges and the largest files of the tree.

#### size Flags

- `--top int`: Number of largest files to report (default 10)

## Architecture

The tool is built with a layered architecture. The dependency direction is
strictly downwards, nothing in a lower layer imports a higher one.

- **Front Ends**: `cmd` for the command line and `internal/gui` for the
  graphical interface. Both are thin adapters over the same engines.
- **Analysis Layer**: `internal/scan` holds the engines. They take an options
  struct, report their progress and return a report structure. They know
  nothing about the front end.
- **Data Model**: `internal/report` holds the structures that flow from the
  engines to the formatters and to the interface.
- **Output Layer**: `internal/output` renders a report as text, JSON, XML or
  HTML.

## Graphical Interface

The same tools are available in a desktop window, built with
[Gio](https://gioui.org). The interface shows a preview of what a tool would
do before it touches the filesystem, and the renaming and organizing pages
ask for a confirmation before they change anything.

The interface is guarded by the `gui` build tag, so the command line tool
stays pure Go and cross compiles to any target as before.

```bash
make build-gui     # Builds bin/filetools-gui
./bin/filetools-gui gui
```

On Linux the build needs cgo and the windowing and graphics libraries of the
platform:

```bash
sudo apt-get install -y \
  gcc pkg-config \
  libegl-dev libgles-dev \
  libvulkan-dev \
  libwayland-dev \
  libx11-dev libx11-xcb-dev libxcursor-dev libxfixes-dev \
  libxkbcommon-dev libxkbcommon-x11-dev
```

On Windows no extra packages are needed. On macOS the build needs the Xcode
command line tools. The release artifacts are
named `filetools-gui-windows-amd64.exe` and `filetools-gui-linux-amd64`.

## Command Reference

### Global Flags

These flags work with all commands:

- `-o, --output string`: Output format (text, json, xml, html) (default "text")
- `-f, --file string`: Output file (default: stdout)
- `-j, --json`: Shortcut for `-o json`
- `-x, --xml`: Shortcut for `-o xml`
- `-w, --html`: Shortcut for `-o html`
- `--exclude-file string`: Exclude files matching patterns (comma-separated globs or file types)
- `--exclude-dir string`: Exclude directories matching patterns (comma-separated globs)
- `--no-progress`: Disable progress indicators

### dupfind Flags

- `-H, --hash string`: Hash algorithm (md5, sha1, sha256) (default "md5")
- `--min-size string`: Only consider files of at least this size (e.g. 1MB, 512K)
- `--max-size string`: Only consider files of at most this size (e.g. 100MB)

### dirstat Flags

The `dirstat` command uses only the global flags (no command-specific flags).

### organize Flags

- `--by string`: Group files by type, extension, date or size (default "type")
- `--dest string`: Destination directory (default: the scanned directory)
- `--force`: Move the files (disables dry-run)
- `--overwrite`: Replace files that already exist at the target
- `--include-hidden`: Also organize hidden files
- `--category string`: Only organize files belonging to this category

### size Flags

- `--top int`: Number of largest files to report (default 10)

### rename

Rename files in a directory using pattern matching and sed-like replacements.

#### Basic Usage

Rename files in a directory:

```bash
filetools rename --match "*.jpg" --sed "s/^/vacation_/" /photos
```

If no directory is specified, it uses the current directory:

```bash
filetools rename --match "*.txt" --sed "s/draft/final/g"
```

#### Output Formats

Choose from multiple output formats:

```bash
# Text output (default)
filetools rename --match "*.jpg" --sed "s/old/new/" /path

# JSON output
filetools rename -o json --match "*.jpg" --sed "s/old/new/" /path

# XML output
filetools rename -o xml --match "*.jpg" --sed "s/old/new/" /path

# HTML output
filetools rename -o html --match "*.jpg" --sed "s/old/new/" /path
```

#### Examples

Add prefix to all JPG files:

```bash
filetools rename --match "*.jpg" --sed "s/^/vacation_/" /photos
```

Remove suffix from files:

```bash
filetools rename --match "*_old.jpg" --sed "s/_old//" /photos
```

General replacement:

```bash
filetools rename --match "*.txt" --sed "s/draft/final/g" /docs
```

#### Dry Run (Default)

By default, the command runs in dry-run mode for safety:

```bash
filetools rename --match "*.jpg" --sed "s/old/new/" /photos
# Shows what would be renamed without making changes
```

To actually perform the renames:

```bash
filetools rename --force --match "*.jpg" --sed "s/old/new/" /photos
```

#### rename Flags

- `--match string`: File pattern to match (glob, required)
- `--sed string`: Sed-style replacement expression (e.g., s/old/new/g, required)
- `--dry-run`: Preview changes without executing (default: true)
- `--force`: Perform actual renames and overwrite existing files

### Adding a New Tool

To add a new tool:

1. Add the analysis engine in `internal/scan/` with an options struct, a
   `progress.Indicator` parameter and a `report.*Result` return value
2. Define the result struct in `internal/report/report.go`
3. Add the formatter to `internal/output/` and to the `OutputFormatter`
   interface
4. Register the Cobra command in `cmd/`
5. Add the interface page in `internal/gui/page_<name>.go`
6. Add tests in `internal/scan/`

### Adding New Output Formats

To add a new output format:

1. Create a new formatter in `internal/output/`
2. Implement the `OutputFormatter` interface
3. Add the format to `NewFormatter()` function
4. Add corresponding flag if needed
5. Update tests and documentation
